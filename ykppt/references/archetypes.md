# 页型配方（archetypes.md）

每个页型给：**用途 → 版式骨架 → 精确坐标 → 内容容量 → DSM 写法**。
坐标单位 1/100 inch，画布 1333×750。页眉已由母版提供，此处只画正文区。

页型名（`type`）是生成器 `scripts/build_deck.py` 识别的 key。

---

## 0. 通用骨架：页眉 + 页码

除 `cover` / `toc` / `closing` 外，所有页型都由母版的
`1_标题和内容` 布局页头部自动继承：

- 章标签 = `section` 字段（如「三、研究内容」）
- 横幅标题 = `title` 字段（≤ 26 字）

页码占位符自动填充 `-N-`。**不要自己在稿子里画页眉**。

---

## 1. `cover` 封面

**何时用**：全篇第一页，仅一次。

```
父版式：空白
形状：
  校徽打底    (0, -14) 766×766   图片填充，左侧淡水印
  图书馆照片  (0, 108) 1333×292  图片填充
  主标题      (34, 421) 1227×91  48pt 粗，深蓝
  汇报人组合  (47, 541) 678×43   深蓝渐变条 + 16pt 白字
```

**字段**
```yaml
type: cover
title: 面向泛在人机物资源协同运行时编程模型   # ≤ 22 字，48pt
presenter: 孙愉祥
advisor: 陈亚兴老师
date: 2026年7月31日
```

**容量**：标题 ≤ 22 字（48pt 下 1227pt 宽约 24 字）；超了分两行，
第二行 y+91。汇报人那行三个字段合计 ≤ 30 字。

---

## 2. `toc` 目录页 / 章节过渡页

**何时用**：全篇开头放一次；**每一章开始前再放一次**，把当前章标题标红。
原 4 份文件里那些「合作QQ」页其实就是这个（水印是第三方模板残留，已删）。

```
左：深蓝面板 (0,0) 354×750；「目录」54pt 粗白字 + 细分隔线 + CONTENTS 20pt
右：白卡 (288,108) 883×527
   5 条，每条 24pt 粗，y = 151 / 245 / 339 / 433 / 528（间距 94）
   每行左侧 28×28 蓝色方块，行下细分隔线
```

**字段**
```yaml
type: toc
current: 研究内容        # 可选；省略则不标红，走「全黑」样式
```

默认 5 条固定为：研究背景 / 相关工作 / 研究内容 / 总结与展望 / 质询与回答。
少于 5 章时，把不用的条目从母版里删掉并重新均分 y（生成器自动做）。

## 3. `lead` 定性句页（最常用，也最容易写坏）

**何时用**：每一页正文的最上方，用**一句 20pt 粗的话**说出本页结论，
下面的图/卡片是这句的论据。这是整套模板的叙事核心。

```
标题：横幅 28pt 粗（母版）
定性句：(53, 111) 1266×77  20pt 粗，1.5 行距，两端对齐
分隔线：(60, 180) 1203     accent2
内容区：y 190 起
```

**字段**
```yaml
type: lead
section: 三、研究内容
title: 关系闭合的资源结构
lead: 亲和性判断资源是否适合协作，局部性判断跨域协作代价是否可接受。
conclusion: 现有运行时缺少对二者的持续对象化管理。
```

**容量**：定性句 ≤ 60 字（超过会压成两行，仍可接受，但三行就说明该拆页）。

## 4. `cards` 卡片页（2 栏 / 3 栏）

**何时用**：并排比较两个方法、两类问题、两条路线。

```
2 栏：
  左卡 (70, 322) 543×300   圆角，渐变白底，描边 PALE2 0.25pt
  右卡 (674, 322) 581×303
  卡片小标题：卡内 y+5，20pt 粗
  卡片正文：卡内 y+78，16pt，1.5 行距

3 栏：均分 x 35..1298，卡间距 32 → 每卡宽 411
```

**字段**
```yaml
type: cards
section: 二、相关工作
title: 关联资源的整体化组织
lead: 现有研究将有关联的资源组织为复合对象、应用资源集合、服务拓扑或执行图。
conclusion: 能整体组织资源，但任务仍需直接协调内部成员及其关系。
cards:
  - head: ASRE
    text: 将容器、消息代理等跨边云异构资源组织为面向特定应用的资源集合……
  - head: TOSCA
    text: 通过节点、需求、能力和关系描述服务结构……
```

**容量**：每卡正文 ≤ 90 字（16pt / 卡宽 543 / 1.5 行距约 5 行）。

## 5. `bullets` 分条页

**何时用**：3–5 条并列要点，不需要卡片框。

```
起始 y 190，每条：
  圆点 ■ 14×14 @ x 60
  文字 (92, y) 1170×auto  16pt，1.5 行距
  条间距 20
```

**字段**
```yaml
type: bullets
section: 三、研究内容
title: 研究思路
lead: 从关系闭包到对象调用，再到跨资源连续执行，三步递进。
bullets:
  - 关系闭合的资源结构：把离散角色组织为边界明确的任务资源对象
  - 对象中心编程与执行：任务只持有稳定对象，内部成员由运行时协调
  - 跨资源连续执行：活动状态与具体资源解耦
```

**容量**：≤ 5 条，每条 ≤ 45 字（两行以内）。

## 6. `flow` 竖向流程页

**何时用**：方法的递进阶段（3–4 步），带箭头。

```
框：(227, y) 835×68   白底，描边 #142E79 1.5pt
框内字：20pt 粗 居中
箭头：(570, y+69) 134×58   实心 #142E79，虚线描边 #002060
步长：178
左侧标注：框旁 x 692，如「对象化」「整体调用」「状态解耦」
```

y 起点 190，4 步到 y 190+3×178+68 = 792 —— **超出画布**。
所以竖向流程最多 **3 步**（190 → 606）。4 步改用 `flow_h` 横向。

**字段**
```yaml
type: flow
section: 三、研究内容
title: 研究思路
lead: 三步递进。
steps:
  - {text: 关系闭合的资源结构, tag: 对象化}
  - {text: HyperContainer,      tag: 整体调用}
  - {text: 跨资源连续执行,       tag: 状态解耦}
```

---

## 7. `flow_h` 横向流程页

**何时用**：4–5 步，或每步文字较长。

```
框：(x, 330) 宽 218 / 高 120     n 步均分 x 35..1298，间距 28
箭头：框间 28×40 居中
步骤号：框上方 40×40 圆，12pt 白字
```

**容量**：每步 ≤ 24 字；5 步时每框 218 宽，16pt 下每行约 2 字 → 只放短标签。

---

## 8. `table` 表格页

**何时用**：系统对照、指标对比（≤ 6 行 × ≤ 3 列）。

```
表头行：高 46，底 #0071C1，16pt 粗白字，居中
数据行：高 41，斑马 #EAF3FA / 白，16pt，居中
全表描边：无外框，仅行分隔线 #5BB0E6
位置：默认 (814, 476) 470 宽；也可指定 x/width
```

**字段**
```yaml
type: table
section: 一、研究背景
title: 亲和性与局部性
lead: 三者对资源抽象的关注点不同。
table:
  head: [系统, 核心抽象]
  rows:
    - [ServiceOS[3], 单设备资源服务]
    - [LegoOS[2], 原子化资源组件]
    - [AIOS[1], LLM 智能体]
```

**容量**：≥ 3 列时每列 ≥ 140 宽；单元格 ≤ 12 字。

---

## 9. `image` 整页图页

**何时用**：自绘的框架图/架构图，占满整页。

```
目标框：x 35..1298 / y 103..642
等比缩放进该框，水平垂直居中
可选图注：12pt 灰 #4E4E4E，放在图下方 12 处
```

**字段**
```yaml
type: image
section: 三、研究内容
title: HyperContainer 三级对象模型
image: assets/figures/hc-model.png
caption: 图 1  HCType—HCCandidate—HCInstance 三级对象模型
```

**铁律**：整页图**不要**塞进「保留标题 + 结论条」的窄条里。
要么占满整页（推荐），要么单独成一页。窄条会糊。

## 10. `close` 结束页

**何时用**：全篇最后一页，仅一次。

```
蓝框 (37, 43) 1260×664 accent1
白框 (75, 76) 1183×598
全景照 (113, 99) 1108×276
「请各位老师同学批评指正！」(257, 441) 819×91  粗体深蓝
分隔线 (262, 538) 809
THANK YOU FOR WATCHING (257, 542) 20pt 灰，字距拉开
```

**字段**
```yaml
type: close
```

固定文案，无需填写。

## 11. 页型选择决策表

| 你手上是什么 | 用哪个 |
|---|---|
| 一句话结论 + 一个并排对照 | `cards` |
| 3–5 条并列理由 | `bullets` |
| 方法的 3 步递进 | `flow` |
| 方法的 4–5 步 | `flow_h` |
| 系统/指标对比 | `table` |
| 自己画的大框架图 | `image` |
| 只有一句重要的话要说 | `lead`（不配内容区） |
| 进入新的一章 | `toc`（`current` 填本章） |

**每页必须有**：`section` + `title` + `lead` + `conclusion`。
缺 `lead` 或 `conclusion`，`verify_deck.py` 会报警——因为这套模板的说服力
全靠「一页一论点」。
